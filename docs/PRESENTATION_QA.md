# Presentation QA and grounding

Before approval, deterministic validation checks count/title slide, stable unique IDs, required topics/evidence coverage, empty slides, title/subtitle/purpose/message, registered slide/block/layout types, evidence scope, citation IDs, native chart/table shape, finite chart values, text/bullet/table/notes/IR limits, placeholders and paths/code/assets. Intentional IMAGE_PLACEHOLDER is allowed; accidental TODO/TBD/Lorem ipsum/INSERT HERE/[NAME]/[DATE] fails.

Phase 8's GroundingEvaluator architecture is reused: claims cite exact supplied excerpts and lexical claim terms must be present. Numeric tokens must be exact cited tokens, not arbitrary substrings. Month/day/year and ISO date strings require exact source support. Quote content must be an exact source substring. Chart categories are bound to numeric values in category-delimited source segments; swapping supported values between categories fails. Summary numbers/evidence must occur in body slides; repeated metric labels with different values fail. Unknown/cross-project evidence always fails. These conservative checks do not prove semantic truth or validate general calculations.

PresentationReviewerAgent evaluates flow, clarity, audience, one-message focus, hierarchy, density, variety and ending separately. Deterministic exact content/title redundancy checks complement that review. Critic guidance cannot override QA. Repair is bounded to two major revisions and re-runs grounding/review/QA before fresh approval. Repeated unchanged content stops immediately.

Likely overflow uses character/word/bullet/block thresholds plus estimated font lines versus each renderer slot and minimum chart/table height. Dense slides also produce visible warnings. This is not pixel-perfect overflow detection; no PowerPoint, LibreOffice, browser or screenshot engine is installed.

After render, JSZip CRC checks and fast-xml-parser validation inspect content types, presentation package, slide XML count, every XML/relationship file, relationship targets, expected slide titles and text, native table/chart counts, editable shape objects and SHA-256. PptxGenJS charts retain embedded editable workbooks. Text, diagrams, tables and notes are native objects rather than full-slide rasterizations. Structural QA does not verify every chart cache/value or final font appearance. Only files passing QA and final review are registered/downloadable.

Offline tests cover spec bounds, provenance/dedupe/budgets, injection data, cross-project/unknown refs, narrative/storyboard, IR/chart/table/assets, numeric/date/summary grounding, density/placeholders, canonical fingerprints, human approval/stale revisions/rejection, repair/no-progress, editable rendering, download isolation/API MIME and legacy rendering. `tests/phase9-live.mjs` reports local model latency separately from deterministic timings and removes its synthetic artifacts.
