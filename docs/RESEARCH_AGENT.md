# Phase 5 research workflow

`POST /api/agent/research/jobs` creates a project-scoped research job with `projectId`, `question`, and optional `topK` (1–10), `maxContextTokens` (1–5000), and `maxAttempts` (1–3). `POST /api/agent/research/jobs/:id/run` executes it; `GET /api/agent/research/jobs/:id` returns task, tool, evaluation, and model evidence plus a `groundedResult` only after completion.

The existing Orchestrator selects the research Planner, read-only ResearchKnowledgeAgent, research Critic, and Final Reviewer. The agent requests `knowledge.retrieve` through the existing Tool Registry and Permission Policy. The tool uses the job's project ID, then the Knowledge Hub retrieves ranked chunks and builds bounded context. The agent calls the existing Model Gateway and asks for JSON claims with chunk IDs and exact quotes. Retrieved text stays in the untrusted knowledge portion of the model input.

The deterministic GroundingEvaluator requires each factual claim to cite a retrieved chunk, include an exact quote from that chunk, and use significant terms present in its quotes. It rejects missing, forged, or lexically unsupported citations. This is a conservative structural check, not a semantic proof of truth. Unsupported claims trigger targeted query planning and a bounded retry; repeated issue fingerprints stop the job. Final review requires a passing evaluation and either cited claims or a valid abstention. No answer is promoted as final on failure.

When the sources do not support an answer, a valid empty-claims model response becomes a first-class abstention with an explicit answer and limitation, no citations, and a passing grounding evaluation only when retrieved text has no relevant question terms. Malformed output and model errors cannot become abstentions. The relevance gate is lexical and can miss semantic paraphrases; relevant retrieved evidence still requires cited claims. The research API returns `limitations` with the grounded result.

Automated tests use fake chat and embedding providers with the in-memory vector store. The optional `tests/phase5-2-live.mjs` validates real Ollama and Qdrant through the server in explicit stages; it is not part of normal tests. The research job and model-call histories are process-local. This phase adds no file-editing agent or privileged tool.
