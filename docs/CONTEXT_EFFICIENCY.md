# Context efficiency and model boundary

`ContextBudgetManager` estimates tokens conservatively at roughly four characters per token. It ranks and deduplicates candidate context, enforces configured budgets, and reports `LOW`, `MEDIUM`, `HIGH`, or `TRUNCATED`. Mandatory security constraints remain outside optional compression. A task handoff contains artifact IDs and a short summary; specialists load the relevant section from `DEVELOPMENT_CONTEXT`, `PATCH_PROPOSAL`, review, or test artifacts. The TestAgent sends a short failure excerpt while the full bounded result remains retrievable.

Default developer budget is 4,000 estimated tokens, with 8 files, 3 ranges per file, 3 Qdrant chunks, and 20 symbols. Environment variables are documented in `DEVELOPER_TEAM.md`. A job's `developmentState.metrics` records estimated tokens, context bytes, file/chunk counts, pressure, artifact references reused, model calls, and provider usage when returned. These metrics are diagnostics, not exact billing savings.

Lossy compression is limited to verbose logs, terminal output, search descriptions, and repetitive JSON. Exact patches, hashes, approval records, test command definitions, error codes, artifact IDs, source code, and security rules stay exact. The optional compression hook requires a recovery handle and falls back to the bounded original on failure. No external compressor is required by Darkcry.

Codex signed in through the user's ChatGPT account is the preferred cloud development assistant for this repository. ChatGPT Plus is not an OpenAI API credential. Darkcry runtime defaults to local Ollama and permits `local`, `openai`, and `auto` selection by job. `openai` requires a separately configured API provider, which Phase 6.1 does not configure. Codex plan usage is visible only through supported Codex UI/status commands; local token estimates do not represent plan quotas.

## External compression evaluation

Headroom 0.37.0 is already installed at the user's Python Scripts path, configured as an enabled Codex MCP server, and exposes compress/retrieve/stats tools in this session. A synthetic 30-line log compressed from 426 to 29 tool-estimated tokens (93.2%) and an exact original was retrieved by hash. This proves one local MCP operation, not automatic interception of Codex context or plan billing savings. The configured proxy reported unreachable during that call. Headroom is optional and Darkcry does not depend on it. See [Headroom MCP documentation](https://github.com/headroomlabs-ai/headroom/blob/main/wiki/mcp.md).

[Caveman Engine](https://github.com/JuliusBrussee/caveman/blob/main/engine/README.md) advertises local shape-specific compressors and exact-byte recovery through a local store. Its Codex profile and native engine require a separate CLI/runtime path. [CCR documentation](https://github.com/JuliusBrussee/caveman/blob/main/docs/technical/context-recovery.md) says the native store is SQLite-backed, defaults to 512 MiB, and is not encrypted or access-controlled by itself. The engine is BSL 1.1 until its stated change date; the thin CLI/SDK is MIT. The project's [Windows guide](https://github.com/JuliusBrussee/caveman/blob/main/docs/install-windows.md) says Codex hooks are disabled on Windows, so automatic Codex integration is limited there. Windows/Codex compression was not verified locally because it was not installed. Recommendation: **REDUNDANT for now**. Headroom already handles the same payload classes and was verified locally. Running both on one payload risks repeated lossy reduction and harder recovery; if evaluated later, assign disjoint payloads and compare exact recovery, latency, and measured output.
